# 2026-09-13

## Built the reader-sync pipeline

Replaced the scratch Readwise scripts with a package that syncs tagged Reader documents to disk.

### Found a silent bug in the old scripts

`readwise.py` and `readwise_favorites.sh` both sent `tags=favorite`. The API parameter is `tag`,
singular. Readwise ignores the unknown parameter and returns no error. Every past run downloaded the
whole library, not the favorites. `readwise2.json` showed the proof: `count: 10000`, and all 100
sampled documents had `tags: {}`.

### Added

- `reader_sync/api.py` — the only module that calls Readwise. Paces requests at 3 seconds to respect
  the 20 per minute limit. Honors `Retry-After` on a 429. Dropped `verify=False` from the old
  script, which disabled TLS checks for no reason.
- `reader_sync/state.py` — watermarks in `documents/.sync_state.json`. Uses the newest `updated_at`
  in the response, not the wall clock, so a record written during a run cannot be skipped.
- `reader_sync/writers.py` — writes the three products. Strips `html_content` from metadata because
  the same bytes already go to `resources/`.
- `reader_sync/pipeline.py` — orchestration.
- `reader_sync/cli.py` and `__main__.py` — `python -m reader_sync sync`.
- `tests/` and a `Makefile`. `make test` runs the docstring examples through unittest. No package
  beyond the standard library.
- `README.md`, and the plan at `docs/reader-sync-plan.md`.

### Decisions

- Content comes from `source_url` first. On any failure the pipeline falls back to the copy Readwise
  stored. The metadata records which source won under `resource.origin`.
- Highlights come from `/api/v2/export/`, which groups them per document and links back through
  `external_id`. The v3 endpoint has no `parentId` filter.
- A run that meets a new document fetches the full highlight export. A document tagged today can
  hold highlights made a year ago, and an incremental fetch would miss them.
- Filenames are `<id>__<slug>`. The id leads so a retitled document is still found by a glob.

### Removed

Deleted `readwise.py`, `readwise_favorites.sh` and five JSON dumps, about 31 MB. All were untracked.
Every dump held the whole library because of the `tag` bug.

### Verified

- `make test`: 10 doctests pass.
- Offline end-to-end run with the network stubbed: the fallback fires on a dead link, child
  documents stay out, highlights from other Readwise sources stay out, a second run writes nothing,
  and a tag change discards the watermark.
- A missing `READWISE_API_TOKEN` exits 1 with a message and no traceback.

### Open

Nobody has run the pipeline against the live API yet. The token is not set in the agent shell.
